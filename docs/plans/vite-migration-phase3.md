# P3 — Production gateway and independent Host supervision

Status: **progress**. Increment 1 completes native production serving; increment 2 completes external paired generations and the separate Host selection/start contract. The live Host still launches the existing Next build; no live Host/Backend restart or deployment switch has been performed.

## Increment 1 — pinned production SPA delivery

- `gateway/src/static.mjs` validates an explicit absolute build directory before opening the listener, then pins regular-file bytes in a finite in-memory snapshot (128 MiB/4096 files maximum). Requests perform no filesystem lookup. Editing/deleting that directory afterward cannot change the running generation.
- Dispatch: reject unsafe raw static targets and API paths escaping their namespace; preserve existing API canonical redirects; run the existing auth gate; handle the exact public display bootstrap; handle `/api` and `/api/*` exclusively as API; then serve emitted resources or the seven known extensionless screen routes. Unknown APIs, errors and nonexistent resources never become entry HTML.
- Root/file/directory links, traversal, encoded separators/double escapes, hidden files, NTFS aliases, unknown MIME types, source maps, reserved namespace files, other HTML, missing emitted entry references and HTML without a Vite module entry fail closed. Startup reads use no-follow where available and verify opened file identity and unchanged metadata/size.
- Entry HTML and errors use `no-store`; Vite default eight-character-hashed asset names use one-year immutable caching; other public files revalidate. Assets use weak SHA256 ETags (including compressed representations), GET/HEAD conditional 304, explicit MIME and `nosniff`. HTML never returns a conditional stale 304. HEAD suppresses bytes but retains original content length.
- Only emitted non-HTML resources/resource namespaces become public to load Login. Protected screens/API retain Cookie/Bearer/token-cleanup/rotation/Origin policy. The shared Next public-path policy is unchanged. Missing resource requests return JSON404 rather than Login HTML redirects.
- Default `gateway` start requires `LEAFCODE_PI_SPA_DIR` and fails before listening if absent/empty/relative/missing/broken. It never launches Vite dev/preview. Explicit `--api-only` / `npm run start:api` preserves the P1 transport-only comparison mode; the P1 comparison launcher now opts into it.
- Gateway build permissions add filesystem/hash/path capabilities solely to the static snapshot reader; entry/router/relays still cannot acquire OS/process/SDK/owner capabilities. The frozen business inventory stays **165 routes / 265 operations**, with **252 emitted runtime modules**.

## Increment 2 — sealed external build generations

- `scripts/spa-build-generation.mjs` uses the established `resolveMirrorRoot` under a reserved `.spa` namespace. Legacy Next synchronization now preserves this namespace. Paths overlapping the checkout/OneDrive or using linked ancestors/workspaces are rejected. Web/shared/gateway build inputs are copied by value, not hard-linked; Backend/Host/extensions, source dependencies, dotenv, hidden files, tests and existing outputs are excluded. Build children receive only system-path variables and explicit production flags, not provider/backend credentials or `NODE_OPTIONS`.
- A private workspace retains only build dependencies. The isolated worker preserves the SPA type configuration and rejects Next/legacy-bridge type sources, then runs real Vite production and the frozen gateway compiler. Runtime generations contain only static SPA output, compiled ingress, and the exact locked Undici runtime dependency; no Vite dev/preview or Next package is a runtime option.
- Exclusive writer lock, unique staging directory, full static-entry/dependency/165-route/265-operation validation, source-change rejection, per-file SHA256 sealing, and a complete-directory rename precede atomic `state.json` replacement. Readers select one UUID pair, never independent frontend/backend outputs. Failed compile/install/validation/publication leaves the old pointer/bytes unchanged. Sealed orphans are not selected. All old generations remain available to running processes; no automatic pruning occurs.
- Selection rechecks regular-file/link policy, the complete hash inventory and pair validity. Corrupt current output can select a verified previous generation; missing/corrupt current and previous fail explicitly. Rollback is locked and compares the expected current UUID, so it cannot overwrite a newer publication. A rollback drops the failed target rather than creating an oscillating fallback loop.
- `host/src/spa-build.js` exposes reuse/rebuild/verified-old-generation retention and start-failure/corrupt-output recovery contracts. Callers supply the native start callback; these helpers have no Backend start/stop/session/lease capability. They are **not yet wired into `host/src/index.js`**. The live Host remains Next; no live deployment, restart or SDK/provider operation occurred.
- Operational limits: current integration evidence is Windows with the installed Node/npm layout. Power-loss durability and hostile same-user mutation of the private build workspace are not established. A killed writer can leave `build.lock`; it is deliberately not auto-stolen. After confirming no writer remains, an operator must recover that private lock. Unselected sealed/staging orphans and retained old generations require controlled cleanup, never deletion of a generation used by a running process.
