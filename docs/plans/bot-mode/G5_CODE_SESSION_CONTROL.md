# G5 Bot→Code セッション制御

## 最小API

Botごとに `codeSessionTaskId` を1件だけ保持し、Code側の既存ハーネスAPIを再利用する。

- `GET /api/bots/:id/code-session` — リンク済みCodeタスクの軽量ステータス
- `POST /api/bots/:id/code-session` — 登録済み `projectId` に対してCodeタスクを起動
- `PATCH /api/bots/:id/code-session` — `{ action: "prompt", prompt }` または `{ action: "abort" }`

起動時は `projectId` を必須にして任意パスを受け付けない。Bot設定のモデル・思考レベルを既定値として使い、権限モード未指定時は安全側の `ask` を使う。同一Botに既存の非アーカイブCodeタスクがある場合は409で二重起動を拒否する。

## UI

Bot設定パネルにCodeセッションカードを追加した。登録済みプロジェクトを選び、指示を送って起動できる。起動後はCode画面へのリンク、ステータス、追加入力、停止を提供する。実行中は2秒間隔で軽量ステータスを更新する。

## 別枠受け入れに残すリスク

- 起動直列化はWebプロセス内のロック。複数プロセス／複数ホスト間の同時POSTは別途検証が必要。
- 再起動後は永続リンクからタスク概要を読めるが、孤児タスクの掃除・セッション再アタッチ・SSE再接続の完全な回帰保証はこのG5では行わない。
- Code側の既存SSE、ハング復帰、孤児タスク処理の受け入れはPhase-D相当の別ハーネスで確認する。
- 標準のWebUI認証／ローカル運用境界を前提とし、Botごとの追加認可層は追加していない。
