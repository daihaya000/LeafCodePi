# G5 Bot→Code セッション制御

## ユーザー ⇄ Bot ⇄ Code

従来の「ユーザー ⇄ Code」に加え、Botが代理でCodeへ依頼し、結果をBot経由で報告する往復を用意した。Code画面を開かずに完結できる。

- Bot専用ツール `code_session`（`projects` / `start` / `prompt` / `status` / `abort`）を1:1Botのセッションだけに登録する。Bot idはモデル入力ではなく実行中のタスクから決める。
- `start` / `prompt` は実行前にユーザー承認を必須にし、対象は登録済み・非アーカイブのプロジェクトに限る。Codeは常に `ask` で起動し、Bot経由で権限を昇格させない。
- 依頼は `dataDir()/bot-code-requests/<id>.json` に永続化する。idは（Botタスク・セッション・tool call）から導出し、同じtool callの再実行や再送で二重起動しない。
- Codeの実行終了後、その依頼のキュー項目から結果を確定し、未配送分をBotへ内部メッセージとして配送する。Botが実際に応答を返すまで配送済みにしないため、再起動やエラーでも報告が消えない。
- 停止・失敗・セッション削除は成功と区別して報告する。Code出力は実行データとして扱い、指示として実行しない旨を配送時に明示する。
- Codeの権限確認・質問はBot会話のカードに中継し、回答は元の要求へ返す。依頼元Botと当該Codeタスクだけが応答できる。

## 最小API

Botごとに `codeSessionTaskId` を1件だけ保持し、Code側の既存ハーネスAPIを再利用する。

- `GET /api/bots/:id/code-session` — リンク済みCodeタスクの軽量ステータス
- `POST /api/bots/:id/code-session` — 登録済み `projectId` に対してCodeタスクを起動
- `PATCH /api/bots/:id/code-session` — `{ action: "prompt", prompt }` または `{ action: "abort" }`

起動時は `projectId` を必須にして任意パスを受け付けない。Bot設定のモデル・思考レベルを既定値として使い、権限モード未指定時は安全側の `ask` を使う。同一Botに既存の非アーカイブCodeタスクがある場合は409で二重起動を拒否する。

## UI

Bot設定パネルにCodeセッションカードを追加した。登録済みプロジェクトを選び、指示を送って起動できる。起動後はCode画面へのリンク、ステータス、追加入力、停止を提供する。実行中は2秒間隔で軽量ステータスを更新する。

## 別枠受け入れに残すリスク

- 未配送結果の走査は2秒間隔のファイルスキャン。件数が増える場合は索引化が必要。
- 同時に保持できる依頼はBotごとに1件。並行依頼は未対応。
- 再起動後は永続リンクからタスク概要を読めるが、孤児タスクの掃除・セッション再アタッチ・SSE再接続の完全な回帰保証はこのG5では行わない。
- Code側の既存SSE、ハング復帰、孤児タスク処理の受け入れはPhase-D相当の別ハーネスで確認する。
- 標準のWebUI認証／ローカル運用境界を前提とし、Botごとの追加認可層は追加していない。
