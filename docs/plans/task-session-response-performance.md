# タスクセッションのレスポンス改善施策

## 目的

タスク画面の「開いてから見えるまで」と、生成中のストリーミング更新を短くする。Pi のモデル生成時間そのものではなく、WebUI/BFF の待ち時間・転送量・再描画量を対象にする。

## 確認したボトルネック

1. SSE の最初のイベントが `ensureLive()` 完了後だった。冷えたセッションでは、Pi runtime 初期化・リソース読込・拡張 bind が完了するまでタイトルすら表示されない。
2. 高頻度の `message_update` / `tool_execution_update` が、毎回セッション履歴全体を `snapshot` として転送していた。
3. `turn_start` / `turn_end` / `entry_appended` は現行 TaskView の表示を変えないのに、通常の全体スナップショットを生成していた。
4. 再接続時に空の初期スナップショットを受け取ると、既に表示していた履歴を一時的に消せる状態だった。

## 今回の実装

- **即時 bootstrap**: SSE 接続直後にストアのタスク概要だけを返し、Pi セッションの hydration は後続の `ready` スナップショットで更新する。
- **delta イベント**: 高頻度更新は最新メッセージ 1 件と必要なメタデータだけを `delta` として送る。履歴全体は再送しない。
- **不要イベント抑制**: 描画に影響しないセッションライフサイクルイベントの全体スナップショットを生成しない。
- **表示状態の明示**: 初回 hydration 中は `role=status` の準備中表示、通信断時はエラーと区別した再接続表示を出す。再接続の空 bootstrap では既存履歴を保持する。
- **クライアント upsert**: delta は全履歴の fingerprint 計算を避け、対象メッセージだけを更新する。

## 受け入れ条件

- 既存タスクを開くと、Pi セッションの準備完了を待たずタイトルと準備中状態が表示される。
- `ready` 後は従来どおり履歴・ToDo・権限要求・質問要求が表示される。
- 生成中は delta 更新で最新メッセージが伸び、既存メッセージの参照が不要に置き換わらない。
- SSE 再接続中は既存履歴を消さず、再接続完了後に通常表示へ戻る。
- 1 ペイン/複数ペイン、モバイル幅、キーボード操作、`prefers-reduced-motion` の既存挙動を変更しない。

## 残す施策（計測後）

- 実ブラウザの長大履歴で `content-visibility: auto` または仮想化を比較する。
- Server-Timing とブラウザ Performance API で bootstrap TTFB、ready 到達、delta 頻度を計測する。
- 実測で BFF CPU が支配的なら、最新メッセージの投影を履歴全体から分離する。

仮想化はスクロール位置・メッセージナビゲーションとの互換性確認が必要なため、今回の最小変更には含めない。
