# セッション内検索とブックマーク

Codeセッションのヘッダーにある **セッション内を検索**（またはCtrl/⌘+F）で検索バーを開く。メッセージ下の **ブックマーク** で後から戻りたい発言に印を付け、検索バーの🔖から一覧・ジャンプ・削除できる。

## 検索

- 対象はユーザー発言とアシスタント応答の **本文**。思考・ツール入出力・メタ情報・圧縮要約は対象外。
- セッション全体を探す。画面に読み込んでいない過去ページの一致も見つかり、選ぶと必要なページを読み込んでから移動する。
- 語は空白区切りで **すべて含む**メッセージが一致。`"..."` で句をまとめる。大文字小文字・全角半角・空白の種類は区別しない。
- 検索語を打つと0.3秒後に検索し、**最新の一致**へ移動する。Enter／▼で次、Shift+Enter／▲で前（端で循環）。件数表示（`3/12`）から一覧を開き、結果を選んで移動できる。一致が200件を超えると新しい200件だけを返す。
- 一致箇所はタイムライン上でハイライトし（CSS Custom Highlight API。非対応ブラウザでは行の強調のみ）、移動先のメッセージ行を淡く強調する。畳まれた作業ログ内の本文は自動で開く。複数語の検索では、全語を含むメッセージだけをハイライトする。
- Escで一覧→検索バーの順に閉じる。閉じてもキーワードは覚えており、再度開くと同じ検索語で結果を更新する（タイムラインは動かさない）。
- Ctrl/⌘+Fは、そのペイン内にフォーカスがあるとき、またはフォーカスがページ自体にありペインが1つだけのときに奪う。それ以外はブラウザの検索に任せる。

## ブックマーク

- ユーザー発言は「入力欄に戻す／ここから分岐」の行、アシスタント応答は吹き出し下に **ブックマーク** ボタンを出す。作業ログ内のメッセージ・生成中でまだ保存されていないメッセージ・Bot会話には出さない。
- 一覧は時系列順。選ぶと該当メッセージへ移動して2秒強調する。巻き戻しなどで履歴から消えたものは「履歴に見つかりません」と表示し、移動できず削除だけできる。
- 1セッション500件まで。

## 実装

| 役割 | 場所 |
| --- | --- |
| 語の分解・畳み込み・一致範囲・抜粋（サーバーとブラウザで共有） | `shared/text-search.mjs` |
| メッセージ検索（本文抽出・上限・永続ID判定） | `shared/task-search.mjs` |
| ブックマーク永続化 | `backend/core/task-bookmark-store.mjs` → `<dataDir>/task-bookmarks.json` |
| 全文の取得（Backend所有時はBackendのdetail、それ以外はディスク上のtranscript。3秒だけ読み取りを共有） | `web/src/lib/task-transcript.ts` |
| DOM上の一致・ハイライト・スクロール | `web/src/lib/dom-find.ts` |
| 状態・ジャンプ・履歴読み込み・ショートカット | `web/src/components/task/use-task-find.ts` |
| 検索バー・一覧 | `web/src/components/task/TaskFindPanel.tsx` |

API（いずれも `Code` タスクのID。存在しなければ404）:

- `GET /api/tasks/:id/search?q=&limit=` → `{ terms, total, truncated, hits: [{ messageId, role, createdAt, snippet, highlights, count }] }`
- `GET /api/tasks/:id/bookmarks[?verify=1]` → `{ bookmarks, missing? }`。`verify=1` はtranscriptを1回読み、履歴にないIDを `missing` で返す（読めないときは省く）。
- `PUT /api/tasks/:id/bookmarks` に `{ messageId, role, messageCreatedAt, preview }` → `{ bookmarks }`。同じメッセージの再追加は最初の1件を保つ。
- `DELETE /api/tasks/:id/bookmarks?messageId=` → `{ bookmarks }`

メッセージは **セッションエントリID** で指す。ストリーミング中の `msg-<index>` は永続化で別のIDに置き換わるため、検索・ブックマークの対象にしない。PUT/DELETEは別オリジンからの要求を403にする。

ブラウザ側の規約: タイムライン行は `data-message-ids`（行が描くメッセージID、空白区切り）、メッセージの `<article>` は `data-message-id`、検索対象の本文要素は `data-search-text` を持つ。`::highlight()` は現行のCSSビルドが解釈できないため、`dom-find.ts` がペインごとに一意な名前の `<style>` とHighlightを実行時に作る。色は `globals.css` の `--find-*`。

## 限界

- 思考・ツール出力の検索、BotやRoomの会話での検索・ブックマークは未対応。
- 検索結果はtranscriptを読み取った時点のスナップショット。直近3秒の読み取りを再利用するため、実行中に増えた発言が一覧へ反映されるまで最大3秒程度かかる（単語1つの検索ではタイムライン上のハイライトにはすぐ反映される）。
- マークダウンの記法（リンク先URLなど）は生のテキストで一致判定するため、画面に出ない文字で一致する場合は行の強調だけになる。
- 巨大なセッションでは、検索のたびにtranscript全体を読む（3秒以内の再検索は共有）。
