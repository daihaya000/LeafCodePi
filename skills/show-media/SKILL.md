# Show Media — メッセージで画像・動画・音声を見せる

Code・Bot・Room の返信で画像・動画・音声を見せたいときに使う。WebUIのハーネスはスキルとは独立してメディア表示を案内する。

## ハーネス標準の `show_image`

ツールが利用可能なら、提示するローカル画像を `show_image({ images: [{ path: "renders/render.png", alt: "完成したレンダー" }] })` で登録する。

- 既存ファイル・対応形式・32 MB上限・タスクの許可パスを画像APIと同じ規則で検証する。HTTP URL・ネットワークパス・SVGは登録できない。`file://`ではなく通常のファイルパスを渡す。
- 検証済み画像が最終返信から漏れた場合、ハーネスがMarkdown画像を補完する。画像を見せる目的で登録したものだけが対象。生成ツールの出力・内部確認用スクリーンショットは自動登録しない。
- 1返信で最大8画像。新しい依頼では登録をリセットする。ユーザーが画像表示不要と指定した場合は登録しない。
- モデルに画像データを渡すツールではない。内容の確認が必要なら、先に `read` 等で目視確認する。
- 利用不可（権限・旧ハーネス・タスクなし）の場合は、次のMarkdown構文で直接埋め込む。パスや生成完了の報告だけで終えない。

Markdown画像構文で書くと、WebUIが画像として描画する（クリックで拡大表示）。

## 動画・音声のハーネス標準ツール

- 動画: `show_video({ videos: [{ path: "renders/clip.mp4", alt: "完成動画" }] })`。
- 音声: `show_audio({ audio: [{ path: "output/music.wav", alt: "生成した音楽" }] })`。
- 各種類1返信最大8件、1ファイル512 MB以下。許可パス・拡張子・ヘッダーを検証する。URL・UNC・SVG等は登録できない。
- 動画: MP4・M4V・MOV・WebM。音声: MP3・WAV・M4A・AAC・OGG・Opus・FLAC・WebA。コンテナの検証だけで再生可否は保証しない（ブラウザ・コーデック依存）。
- 登録した動画・音声の最終返信への埋め込み漏れを、画像と同じく追加モデル呼び出しなしで補完する。内部確認用・表示不要指定の種類は登録しない。画像・動画・音声の許可と表示不要は独立。
- 内容の解析・文字起こしツールではない。内容の確認が必要なら対応ツールで先に検証する。
- ツールが使えない場合も `![動画の説明](<renders/clip.mp4>)` / `![音声の説明](<output/music.wav>)` を使える。対応WebUIは再生コントロール付き動画・音声プレイヤーとして描画する。自動再生・事前読み込みなし。シーク用Range配信、ダウンロード付き。
- 外部の動画・音声URLはクリック時に別タブで開く。勝手に読み込み・再生しない。秘密をURLに入れない。

## 書き方

```markdown
![説明文](/absolute/path/to/render.png)
![説明文](renders/render.png)
```

- パスは**絶対パス**か**タスク作業フォルダー起点の相対パス**（プロジェクトタスクはプロジェクトルート起点）。`~/` と `file://` も使える。
- 空白や日本語を含むパスは `<>` で囲む: `![説明](<my render/結果 image.png>)`
- 対応形式: PNG・JPEG・GIF・WebP・AVIF・BMP（32 MB以下）。**SVGは表示できない**。
- ネットワークパス（`\\server\share`）は表示できない。

## 外部URL画像

- `https://...` の画像は、ユーザーがクリックするまで読み込まれない（プレビュー表示になる）。
- URLに秘密情報を入れない。URLを使ったデータ送信に使わない。ローカルに保存できる画像はローカルで見せる。

## 注意

- 画像はメッセージの表示時にファイルから読み込まれる。見せた後にファイルを削除・移動すると表示が壊れる。
- 存在しないパス・対応外の形式は、画像の代わいに理由付きの表示になる（エラーにはならない）。
- TTS読み上げでは代替テキスト（`![...]` の説明文）だけが読まれるため、説明文は内容が分かるものにする。
